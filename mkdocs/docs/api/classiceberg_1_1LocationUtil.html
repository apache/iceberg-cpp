static bool iceberg::LocationUtil::HasScheme ( std::string_view  location)
static

Whether a location starts with a URI scheme.

This is the spec's test for an absolute path (see "Paths in Metadata"): the text before the first colon must be a non-empty RFC 3986 scheme. It is strict on every platform: unlike ParseScheme, a single letter such as C: counts as a scheme.

static std::string_view iceberg::LocationUtil::ParseScheme ( std::string_view  location)
static

Extract the URI scheme from a location.

This follows Java's ResolvingFileIO: the text before the first colon is the scheme; an empty result means that no scheme was found. Text that is not syntactically a scheme (RFC 3986) yields no scheme, and on Windows a single letter is a drive rather than a scheme. The rest of the location is not validated.

Relativize a location against a table location.

If the location starts with the table location immediately followed by /, the remainder after that separator is returned. Otherwise the location is returned unchanged. A table location that ends in / already includes the separator.

Resolve a location against a table location.

A location with a URI scheme is absolute and is returned unchanged. Otherwise the result is table_location + "/" + location, with no / added when the table location already ends in one. The join does not interpret . or .., and a location starting with / yields //.
